# V-Life 前端重构阶段汇报

汇报日期：2026 年 10 月 1 日。范围：本轮 UIArc 原始组件接入，以及此前 Figma 提案与当前运行版的关系。

本轮实际改动覆盖 **记账、待办、日程三个业务页面，加上全局功能搜索和组件运行环境**。记账的变化最集中；待办改了筛选、分组、详情编辑和批量归档；日程改了视图切换和从待办创建日程的选择器。

**当前是局部重构的本地运行版，尚未完成整站重构。** 你正在查看的热量页面没有做页面主体改造。代码保存在本地分支 `codex/uiarc-runtime`，尚未提交、推送或部署。

## 各板块具体改了什么

### 待办事项

分组选择改为官方 SegmentedControl，直接控制按分类、按重要性和全部三种任务视图。

新增官方 FilterToolbar，按分类、完成状态和归档状态筛选任务，支持删除单个筛选条件与清空全部条件。切换中英文后，已选条件仍然有效。

展开任务后的详情使用官方 InlineEdit 就地编辑，提交连接原有任务更新接口，失败时回退。

批量归档改为官方 ConfirmMorph，依次展示确认、处理中、成功、失败重试和撤销状态。归档与撤销等待实际操作结果；部分失败后重试会保留本次成功归档的任务范围，撤销只恢复对应批次。

### 日程计划

日、3 天、周、月的选择改为官方 SegmentedControl，其选择状态直接控制现有日历视图，也支持原组件的键盘操作。

新建日程时，“从待办快速选择”改为官方 Combobox。可以搜索未完成任务，选中后把任务标题和详情带入日程表单，保留父子任务的名称关系。

本轮没有重写日历网格、事件卡片、时间轴或整套日程编辑流程。

### 记账

日期范围选择改为官方 DateRangePicker。筛选后的同一组记录同时驱动金额、分类环图、支出折线、预算进度和分周明细。切换月份会清除旧日期范围，避免出现上一月份条件仍生效的问题。

金额显示、分类分布和支出趋势分别使用官方 AnimatedCounter、DonutChart、LineChart。验证中，两笔演示记录合计 100 元；筛选其中一天后，金额、图表和明细同时变为 40 元。

新增和编辑记录使用官方 BottomSheet，支持拖动到不同高度。分类选择使用 Combobox，金额输入使用 NumberField；保留人民币、日元、美元及历史汇率相关逻辑。

保存按钮使用官方 ActionButton，等待真实保存操作后才显示成功。等待期间阻止重复提交；失败保留草稿；成功后锁定已保存字段，让用户关闭抽屉后继续记账。

月度归属继续使用 V-Life 原有的按周归月规则，具体由该周的星期三决定月份。因此跨月周内的记录可能出现在相邻月份，这不是本轮新增的统计规则。

### 全局功能搜索

页面顶部新增原组件 Button 与 CommandPalette 组成的搜索入口。支持快捷键打开、输入名称过滤、方向键选择、Enter 跳转，以及 Esc 清空搜索后关闭。

菜单包含 17 个候选功能入口，并根据功能隐藏设置和考公专注模式调整可见项。这里搜索的是功能页面，不是所有任务、账单、笔记的全文内容。

## 哪些页面还没有改

下列页面的内部界面在本轮没有直接修改：

- 首页概览、今日待办。
- 热量记录、减肥专项。
- 食材管理、用品管理。
- 项目管理、目标。
- 随想、学习笔记。
- 生活日报。
- 考公、运势及其子页面、商店、设置等其他业务页面。

其中使用公共 AppLayout 的页面会获得顶部功能搜索入口，但其卡片、表单、列表和图表仍是原来的实现。侧栏和移动导航也没有整体重画。

因此，如果你在热量页面看到的主要还是原界面，这是当前实际范围所致。不能把公共搜索入口的增加算作热量板块重构。

## 与原版一致到什么程度

已引入 16 个官方组件，保存了 36 个带来源校验的原始文件。**14 种组件已接入业务页面；MetricCard 和 Sparkline 目前只是预备组件，没有接入业务页面。**

| 项目 | 当前实际情况 |
| --- | --- |
| 组件实现、CSS Modules、共享动效参数 | 原始源码按固定版本复制，未修改这些文件；来源校验通过 |
| 官方公开安装包 | 上一轮对照的 16 个组件逻辑和样式一致，差异仅为安装路径 |
| 组件核心依赖 | React 19.3.0、Motion 13.4.0、Lucide 1.47.0、Radix Dialog 1.1.23，与固定来源版本对齐 |
| 组件内部动效状态 | 沿用原组件实现和默认参数 |
| 跨组件数据联动 | 接入 V-Life 的记录、筛选和操作结果；未复制 UIArc Pro 完整场景的数据编排 |
| 页面外层框架 | V-Life 继续使用 Vite，没有迁移到 UIArc 网站使用的 Next.js |
| 样式与主题适配 | 在原文件之外做样式作用域隔离与主题同步，加载 Inter 和 Geist；中文使用浏览器字体回退 |
| 全站或完整场景复刻 | 尚未完成，也未验证跨设备逐帧一致 |

原始来源为 [UIArc 公开仓库](https://github.com/kuratlielia/arc-library/tree/b454cf80c5378d9d1ef846fe1c352e3068281b8d)，固定提交为 `b454cf80c5378d9d1ef846fe1c352e3068281b8d`，采用 MIT 许可。

当前取得的公开源码没有包含 UIArc Pro 钱包／财务完整场景。因此，可以核对已采用的原组件源码和动效逻辑，但不能宣称已经完整复刻 Pro 场景的所有动画联动。

## Figma 与当前运行版的关系

在你强调原版动画、实现方式和数据联动之后，工作转到真实前端：采用官方 React 组件，通过浏览器验证交互。当前代码改动并不等于已经把所有运行状态重新同步进 Figma。

Figma 设计稿本身不能执行这套 React 与 Motion 代码。对于你要求的动效一致性，当前运行版和源码核对才是验收对象。

## 整站重构还差什么

这一阶段完成了原组件引入及三个页面的局部接入，还需要继续完成：

1. 首页概览与今日待办的整体布局、信息层级和任务交互改造。
2. 热量与减肥页面的指标、记录表单和图表联动。
3. 食材与用品页面的筛选、就地编辑和操作反馈。
4. 已改三个页面中仍沿用原实现的卡片、列表、日历和表单部分。
5. 全站桌面与手机的一致性检查，以及真实账号下的保存、读取验收。
6. 对“完全一致”的验收范围作具体落实：是否迁移外层框架，以及目标完整场景是否有可使用的源码。

建议下一阶段先处理首页、今日待办、热量三个常用入口，再把已经接入的控件推广到重复的业务操作中。以上为后续建议，本次汇报没有执行这些改造。
