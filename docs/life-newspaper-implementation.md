## 已实现

- `/newspapers` 日报库与首页入口：按月份显示折叠报纸侧脊，抽出后在整窗口展开，覆盖侧栏；收回保留原浏览位置与焦点。手机单栏、键盘操作与减少动效模式。
- 共享领域层汇集任务完成、习惯、日程、项目/学习、随想、财务、饮食/运动/身体记录。所有分页读取；关联来源去重并保留原始来源；未知完成时间不推断；部分来源失败单独说明。
- 账户时区与一天起始小时、每日快照和修订、历史补建、来源变更提示与主动刷新、原记录删除后快照保留。归档从启用日开始，空白日期也归档；定时服务不调用 AI。
- 手动补记自动保存原文、修改/删除与并发冲突检测；导出等待尚未保存的输入。可选复盘保存所依据修订，记录变化后标记过期；建议可转成今日待办并回读。
- 独立生图配置、风格预设新建/编辑/复制/删除/默认风格、模板变量、参考图、最终提示词预览与当次覆盖。整期主图和版块图、旧候选保留、图注编辑、大图缩放与下载。
- 持久图片任务与私有原图/缩略图。读取不生成；任务提交、轮询、保存由服务器处理。提交结果不明不自动重试付费；已下载原图存在时可恢复缩略图/入库。账号、权限和图片存储隔离；密钥仅服务端可读，网页只见状态/掩码。
- Markdown 全文、仅素材、类别选择和包含实际图片的 ZIP。复制不含过期私有链接。
- Web、站内 AI、MCP、Agent API 复用 `newspaperOperations` 与同一权限规则。网页与站内 AI 在同一浏览器会话共享持久幂等标识；外部客户端重试须携带原幂等键及原参数，不能用新键猜测重试。

## 发布顺序与配置

1. 在目标 Supabase 项目确认现有 Agent 权限/执行角色迁移已部署，再按顺序应用 `20260928020000_newspaper_reports.sql`、`20260928021000_newspaper_images.sql`。它们创建日报表、修订、补记、复盘请求、图片配置/秘密/任务/资产、私有 `newspaper-images` 存储桶、RLS 和服务端事务函数。
2. 设置至少 24 字符随机值 `NEWSPAPER_WORKER_SECRET` 为 Edge secret。通过 Supabase Vault 安全界面保存同一值，名称 `newspaper_worker_secret`；再保存目标项目 URL，名称 `newspaper_project_url`。不要把值提交到代码库或日志。Vault 名称存在但值错误会使调度失败，须实际检查调用结果。
3. 部署 `newspaper`、`newspaper-archive`、`newspaper-images-worker`，以及更新的 `agent-api`、`mcp-server`、`ai-chat`。`supabase/config.toml` 中三个新函数关闭网关 JWT 检查：用户入口自行验证 JWT，两个定时入口只接受专用 worker secret，绝非公开无认证写入口。
4. `NEWSPAPER_ALLOWED_ORIGINS` 可按部署域名覆写。默认含正式 `https://shenghuo.homes`、localhost 的 5173/8080/4177 端口与 `http://127.0.0.1:4177`；当前线上配置已包含上述地址，其他预览域名需单独加入。
5. 归档在每小时第 7 分钟运行，分批每次最多 10 账户、每账户 3 天；任务游标继续补齐启用后的日期。图片 worker 每分钟调度，默认每次领取 1 个任务，数据库租约防并发重复提交。pg_net 超时 120 秒；目标 Edge 运行限制必须容纳 Gemini 100 秒请求及后续保存。
6. 部署前端。在设置 → 日报开启每日归档、确认时区和一天起始时间，配置各渠道独立 Key 与默认模型/风格。不会复用识图模型配置，不会自动复盘、生图或批量补画往期。
7. 用授权测试账号在真实环境验证自动归档、图片任务关闭页面后继续、私有原图/缩略图回读、账号隔离和接口撤权；再次验证 Grsai VIP 与官方模型组合。不要用真实用户记录制造测试数据。

缩略图使用固定版本 `@imagemagick/magick-wasm@0.0.43`。Edge 若无法直接读取打包 WASM，会使用固定 URL 下载并校验 SHA-256；这是下载处理库，用户图片不会发给该 CDN。部署环境必须支持 WASM 和该资源读取。
