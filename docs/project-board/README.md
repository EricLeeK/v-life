# 项目看板：拖动质感与品牌纹理

2026-11-01。用户批准把独立视频复刻的 UI/动画融入 V-Life，并允许调整功能逻辑。本次是现有 Warm Desk Ledger 品牌的扩展，不替换全站设计。

## 沿用世界与形式范围

用户的“把这套 UI 和动画迁移到我的 Vlife 的项目管理面板里”批准沿用既有导航与 Warm Desk Ledger 品牌，并把已展示的四列原型接入实际功能。FORM 为现有工作台扩展；本轮未重选形式、未抽取随机 seed，也没有可引用的旧 seed，故 seed 不适用，不补造。质量基准是已批准原型 `public/drag-weight/` 与现有 DESIGN.md；未另设营销式 QUALITY BAR card。

## 交互和功能变更

- 默认四列：待办、进行中、等待中、已完成。项目中已有“本周”事项时保留第五列；旧数据无需改写。
- 保持任务、习惯、里程碑三类事项。任务和里程碑按权重计算进度；习惯独立打卡并显示本周天数。
- 当前项目的侧栏与看板从相同工作项计算加权进度，避免旧摘要与实时数值矛盾。手机区分“新建项目”和“新建事项”，拖柄、完成与打卡命中区至少 44×44px。
- 从某列新建时，默认落在该列。里程碑支持一键完成/重新打开。
- 纹理为可保存字段 `cover_preset`：自动、无封面、鼠尾草、暖沙、陶土、雾蓝、鸢尾。自动模式仅为里程碑加鼠尾草封面。
- 配色引用现有 `--cat-*`、背景、卡片和文字语义色，柔和渐变叠加本地颗粒纹理；支持深色主题。
- 拖动位置采用阻尼弹簧，倾斜由移动速度驱动，限制 ±4.5°。停止移动时回正，释放时吸附，邻卡弹簧让位。
- 桌面拖卡、手机拖动手柄、键盘空格拾起/放下和方向键移动。Esc 取消；开启减少动态效果后取消物理摇摆。
- 筛选拖动保留隐藏事项的相对次序。拖动保存失败后恢复服务端状态并提示。

## 设计边界

- 原视频为拖动和布局参考；在真实产品中按品牌和功能适配，不声称逐像素一致。
- 继续使用全站字号、颜色、圆角与图标。检测器对 `calc(var(--radius) - 2px/4px)` 的九处报告是解析截断导致的误报；这些正是 Tailwind 的 md/sm 圆角定义，未增加例外或关闭检查。

### 松手闪烁修复

用户反馈落位瞬间闪烁。逐帧追踪复现：旧流程先移除浮层，再等待 React 提交正式卡片，出现一帧只有占位的空白。现改为同步完成正式卡片交接后再撤浮层，并在落位时用 160ms 收回抬升阴影。`scripts/drag-weight/project-drop-check.mjs` 在 4 倍 CPU 降速下检查跨列、同列、取消和减少动态四种路径，合计 551 帧无空白、无页面异常。

### 不挤动布局的编辑模式

按用户截图调整：项目编辑/删除紧邻项目标题状态，左侧项目列表始终保留原貌。工作项只在编辑模式显示右上角铅笔和圆形删除叉；卡片轻微 ±0.3° 摆动，按钮悬停或焦点进入卡片时暂停，减少动态效果时关闭。普通状态点击卡片不打开编辑器，拖动和独立打卡仍保留。

操作按钮为覆盖层；项目操作区和“编辑/完成编辑”文本保留固定占位。桌面 1600px 与手机 390px 对照测量确认，切换编辑前后头部、列头、卡片及顶部按钮坐标/尺寸不变，侧栏 DOM 不变。保存时顶部按钮使用 aria-disabled 配合点击保护，避免原 disabled 透明度变化导致闪烁。新增回归覆盖普通点击、侧栏保持及保存期间按钮行为，相关 19 项测试通过。

“待办”表示尚未开始、可以着手；“等待中”表示需要反馈、审批或前置事项完成后才能继续。此轮保留两个状态，未迁移事项。

### 拖动提示与角标细节

落位框改为 2px 虚线，采用辅助文字色的 50% 透明度，保持暖灰而非深黑。左侧未选中项目原本没有底色，拖起后会透出后方内容；现只在 carry/settle 期间补上主题卡片实色与阴影，不改变项目选择。卡片铅笔与删除叉改为同一上沿的圆形角标，铅笔在左，44px 命中区互不重叠。

浏览器复现了未选中项目拖动时背景 rgba(0,0,0,0)，修复后为不透明主题卡片色；选择保持原项目。虚线宽度、角标同行和命中区也已实测。样式检测提示仍为既有 calc 圆角 token 的解析误报，本轮未更改或忽略该规则。

用户进一步明确所有项目始终为实体卡片：取消未选中行的透明底和归档行的整体透明度。静止与拖动均不透明；选中通过暖灰底和更清晰的边框区分，另有 aria-current 标记。明暗主题及切换选择时高度不变均已验证。

### 项目进度不随选择变化

修复侧栏在选中时计算实际任务进度、未选中时读取旧 projects.progress 的双来源问题。所有可见项目（包括展开的归档项）现在都订阅自身已有的 project_tasks 查询，并使用看板相同的加权公式；查询未返回时显示“—”，不假装为 0%。选择仅影响样式。回归覆盖切走、未选中时任务更新和重新选择；页面与进度模型合计 18 项测试、TypeScript 检查通过。

### 待办分类复用项目列表拖动

待办“按分类”视图复用项目侧栏的 SortableList / SortableEngine。仅收起分类可从整条标题栏拾起；展开状态和其他视图禁止分类拾起，内部子任务排序保持可用。共享引擎现在只处理自己直属列表项，避免嵌套列表事件被父列表重复接管。支持键盘空格拾起、方向键移动及取消，动效与减少动态偏好由共享组件处理。

顺序按账号保存在当前浏览器 localStorage，演示模式独立；筛选时保留不可见分类的已有顺序。浏览器实测指针拖动、carry 状态、落位不误展开、展开态禁止拾起、键盘排序和刷新持久化均通过。待办原有 19 项测试通过。设计 hook 提及 sortable.module.css 的 6px 焦点轮廓及 2px 插入线圆角，均为本次复用的既有组件细节，本次未修改该样式文件，不为该提示改动共享动效皮肤。

### 首尾落位容错

复现待办分类拖到列表下方 350px 后松手返回原位：单列表 memberAt 原先同时限制横纵边界，超过 32px 就取消。现在单列表仅检查垂直于排序方向的边界，排序方向可任意超出，插入索引自动截到首位/末位；松手事件直接用最终坐标确认目标与索引，避免沿用上一动画帧的落位状态。共享此引擎的项目列表也采用相同行为，分组跨列表判定保留原规则。

浏览器验证：列表下方 450px 松手落末位；远超列表顶部落首位；横向离开仍取消；Escape 在超出首尾时仍可取消，均通过。
