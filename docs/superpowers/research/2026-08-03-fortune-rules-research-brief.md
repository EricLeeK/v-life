## 0. 一句话任务

请对下列全部运势栏目做**深度、可复核、可编码**的规则调研，产出一份「运势规则知识库 + 工程数据规格」，使我们能把当前娱乐向近似算法替换为**学界/术数传统上站得住、工程上可复现**的规则底盘。AI 只负责润色文案，不负责发明规则。

## 1. 产品边界（调研时必须遵守）

### 1.1 产品定位

- 面向日常轻娱乐，语气温柔鼓励，**不做恐吓、诅咒、绝对化断言**。
- **不做**：完整专业命理咨询、合婚、风水布局、医疗/投资建议。
- 规则要严谨，但最终展示文案仍服务「轻快娱乐」；调研需区分：
  - **A. 硬规则**（可计算、可校验、同输入同输出）
  - **B. 软文案模板**（可本地化、可降级、可给 AI 的结构化事实）

### 1.2 工程约束

| 约束 | 要求 |
|------|------|
| 确定性 | 同用户、同日期、同档案 → 今日底分/黄历/月相结果稳定 |
| 可复现随机 | 塔罗/起卦/求签必须支持 `seed` 复现 |
| 可离线 | 硬规则优先本地计算，不依赖联网 API |
| 可降级 | AI 失败时仍有规则底稿可展示 |
| 中英双语 | 关键术语需中英对照表 |
| 时区 | 明确「用户本地日」还是 UTC；推荐：客户端本地 `YYYY-MM-DD` |
| 版权 | 标注资料来源是否可商用；韦特牌图、签文、卦辞等需区分公有领域 / 需自写 / 需授权 |

### 1.3 明确不在本次调研范围

- UI/UX、配色、动效
- 支付、次数限制、社交分享
- AI prompt 工程细节（可附「建议注入的结构化 facts 字段」即可）
- 完整四柱细盘、大运流年恐吓向体系（八字栏目仅到「日柱 + 轻量五行」级别，但日柱算法本身要严谨）

## 3. 现状债务（调研要对齐「从哪里升级」）

以下为当前实现的已知简化，请在报告中逐条对照「严谨版本应如何纠正」。

| 栏目 | 现状（近似 / 娱乐向） | 主要问题 |
|------|----------------------|----------|
| 黄历宜忌 | 宜忌短语池 + 日期哈希抽样；冲煞随机抽生肖 | **不是**真实黄历；无建除十二神、无真实冲煞合害、无吉神凶煞体系 |
| 月相 | 固定朔望月周期 + 2000-01-06 新月锚点 | 未用精密星历；相位分界为手写阈值；未处理时区/观测地 |
| 农历标签 | 用毫秒日序伪干支，**不是**真农历月日 | 用户看到的「干支日」可能与真实历书不一致 |
| 生肖 | `(year-4)%12`，按**公历年** | 忽略春节分界；跨年 1–2 月可能属相错误 |
| 星座 | 常见热带黄道日期表 | 未区分热带/恒星；未处理 cusp（交界日）争议与出生时分 |
| 星级底分 | 纯哈希 1–5 星 | 无任何占星/生肖理论依据，仅保证确定性 |
| 塔罗 | 78 张牌名齐全，但 keywords 极简；三牌阵固定 past/present/advice | 缺完整牌义（正逆位）、牌阵变体规范、洗牌/抽牌概率模型说明 |
| 易经 | 铜钱法 6/7/8/9 有；**卦序映射是伪映射**（二进制直接当 1–64） | 未用真正的文王卦序 / 先天八卦→六十四卦正确查表；缺变卦、卦辞爻辞结构化数据 |
| 求签 | 自编 24 签池 | 非传统月老签/观音签等体系；等级分布任意 |
| 八字日柱 | 以 1984-02-02=甲子 为锚的儒略差推日柱；时辰只轻微加权五行 | 需校验锚点与子时换日（晚子时）规则；未做真太阳时；五行统计过简 |
| 规则短评 | 模板句 | 无按星座/生肖/月相/宜忌的组合规则表 |

## 4. 分栏目调研要求（核心）

对每个栏目，调研报告必须包含以下固定小节。缺一视为未完成。

### 4.0 通用小节模板（每个栏目都套用）

1. **定义与流派**：该栏目在传统/现代体系中的标准定义；主流流派差异（列 2–3 种并推荐一种作为工程默认）。  
2. **输入 / 输出契约**：精确到字段名、类型、单位、时区、合法范围。  
3. **算法或查表步骤**：逐步可编码；给出伪代码或流程图。  
4. **权威对照样本**：至少 5 组「输入 → 期望输出」，并注明对照来源（历书、权威软件、经典文献）。  
5. **边界情况**：交界日、闰月、子时、极昼极夜（若相关）、缺失出生时辰等。  
6. **数据资产清单**：需要入库/进代码的静态表（CSV/JSON 字段设计）。  
7. **版权与引用**：来源分级（公有领域 / 需改写 / 不可直接商用）。  
8. **与 AI 的接口**：建议传给 LLM 的 `facts` JSON schema（只含结构化事实，不含恐吓文案）。  
9. **与现状差异**：对照第 3 节，列出必须替换的点。  
10. **推荐落地优先级**：P0（正确性必需）/ P1（完整体验）/ P2（锦上添花）。

### 4.1 黄历宜忌（含冲煞）

**调研目标：** 可本地生成「某公历日」的宜、忌、冲煞（及你认为首页值得展示的最小附加项）。

必须回答：

- 宜忌条目的传统来源与现代民用黄历常用子集（建议首页各最多 3 条时如何筛选）。  
- 建除十二神、十二值神与宜忌的关系是否纳入首版。  
- 「冲」「煞」「刑害」中，产品首版最小必做集合是什么。  
- 是否必须依赖完整农历转换库；若是，推荐开源历法库标准（需可在 JS/TS 或预生成表中使用）。  
- 给出至少一整月的对照样本（相对某公开黄历 App/万年历）。

**交付物额外要求：**

- `almanac_day` JSON schema  
- 宜忌词表（规范用词，避免低俗/恐吓）  
- 「娱乐友好」改写对照表（例如传统「作灶」→ 产品文案「下厨」）

---

### 4.2 月相

**调研目标：** 给定日期（及可选时间/时区），输出标准月相名、周期位置、照明比例（可选）。

必须回答：

- 8 相 vs 4 相的标准分界（照明比例或月亮黄经差）。  
- 推荐算法：简化朔望月 vs 星历库（如 NASA / 开源 astronomy engine）的精度权衡。  
- 应用应使用「民用日期的本地正午」还是「用户当前时刻」。  
- 每相的中英标准译名 + 非恐吓向短解读模板（各 1–2 句）。

**对照样本：** 至少 10 个日期与权威月相日历交叉验证。

---

### 4.3 农历 / 干支日标签

**调研目标：** 日期条从「伪干支」升级为真实可用标签。

必须回答：

- 公历 → 农历（年/月/日/闰月）的标准算法或推荐库。  
- 日干支、月干支、年干支的计算；与八字日柱是否共用同一套日柱算法（应共用）。  
- 首页展示最小字段建议：如「农历六月初七 · 甲子日」还是更短。  
- 春节前后、闰月、跨时区用户的处理原则。

---

### 4.4 西式星座

**调研目标：** 生日 → 星座的严谨规则 + 日运/详解可用的规则底稿骨架。

必须回答：

- 热带黄道（Tropical）日期边界表（精确到日）；交界日（cusp）如何处理（推荐：按出生时刻；无时刻则标注「交界」或采用保守归属策略）。  
- 是否引入上升星座/月亮星座（产品当前**不强制**；若建议二期再做，请单列）。  
- 「日运」规则底稿：是按太阳星座 × 星期/月相/行星相位近似，还是仅模板库？给出可工程化方案（复杂度可控）。  
- 12 星座中英标准名、元素（火土风气）、模态（基本/固定/变动）表。

---

### 4.5 生肖

**调研目标：** 生日 → 生肖必须按春节（农历正月初一）分界。

必须回答：

- 1900–2100（或产品目标区间）春节公历对照策略：算法 vs 预生成表。  
- 12 生肖地支对应、五行属性、三合六合冲（哪些适合做「今日提醒」轻量规则）。  
- 「生肖日运」可计算的最小规则集（避免纯哈希）。  
- 与黄历「冲生肖」字段的一致性要求。

---

### 4.6 今日星级底分（整体/爱情/事业/财运）

**调研目标：** 把纯随机哈希，升级为「有解释路径、仍保持同日稳定」的评分模型。

必须回答：

- 推荐输入特征：星座、生肖、月相、黄历宜忌 Impetus、星期等，如何映射到 1–5 分。  
- 必须保持：同输入同输出；分数分布不要极端（给出期望分布）。  
- 明确：**不是科学预测**，而是「可复述的仪式化评分」；给出向用户可展示的一行解释因子（如「月相偏满月 · 宜学习」）。  
- 禁止引入恐吓向扣分（如「大凶日直接 1 星」）；若传统为凶，如何软化映射。

---

### 4.7 塔罗（韦特 78 张 · 三牌阵）

**调研目标：** 完整牌义知识库 + 牌阵规则 + 抽牌程序规范。

必须回答：

- Rider–Waite–Smith 体系下 78 张：id、中英名、牌组、正位/逆位核心义（各 2–4 个关键词 + 1 句短义）。  
- 三牌阵「过去 / 现在 / 建议」的经典依据与变体；是否允许凯尔特十字等二期牌阵（可列但不阻塞）。  
- 洗牌与抽牌：有放回/无放回、正逆位概率（传统常约 50%）、seed 复现规范。  
- 牌图版权：商用可用的策略（几何抽象牌面 / 自绘 / 公有领域扫描）。  
- 规则底稿：无 AI 时，如何用三张牌关键词拼出 80–120 字鼓励向短文（模板语法）。

---

### 4.8 易经起卦

**调研目标：** 纠正伪卦序，建立可编码的铜钱起卦 + 本卦/变卦/变爻体系。

必须回答：

- 三枚铜钱法：阴面阳面赋值、6/7/8/9 定义、自下而上装卦。  
- 六十四卦：文王卦序完整表；先天/后天八卦与六爻卦的标准转换表（二进制 ↔ 卦序）。  
- 变爻 → 变卦规则；多变爻时的传统取用流派（推荐一种工程默认，如「多变爻取本卦卦辞」等，需论证）。  
- 卦辞 / 爻辞：是否采用《周易》原文 + 白话；版权与篇幅；产品首版最小数据集（64 卦辞 + 常用爻辞？）。  
- 给出至少 3 组手工起卦样例（硬币序列 → 本卦名 → 变卦名）。

### 4.9 求签

**调研目标：** 选定一种可完整落地的签谱体系（或自洽的产品签谱规范）。

必须回答：

- 对比常见体系：观音签（通常 100 签）、黄大仙签、月老签、关帝签等；推荐一种并说明理由（完整性、版权、语气可控）。  
- 若因版权无法直接使用传统签文：给出「自建 100 签」的等级分布、主题分类、文案规范（吉凶等级、禁止恐吓）。  
- 抽签随机模型与 seed；是否需要「每日一签」与「一事一签」两种模式。  
- 每签数据结构：`id, rank, title, verse, plain_zh, plain_en, themes[]`。

### 4.10 八字日柱（轻量）

**调研目标：** 日柱计算达到可与主流万年历交叉验证；五行展示有依据但不扩展成恐吓细盘。

必须回答：

- 日柱锚点考证（如甲子日对应公历）与算法（儒略日 / 寿星公式等）。  
- **子时换日**：23:00–00:59 是否换日柱的主流处理；产品缺省出生时辰时如何计算日柱。  
- 时柱：有出生小时时是否展示；十二时辰对照表。  
- 五行统计：日干支五行、是否计入月令/时柱；「简图」推荐算法。  
- 明确禁止输出的细盘内容清单（大运、流年凶断、疾厄等）。  
- 至少 10 组生日（含边界时辰）对照权威万年历日柱。

### 4.11 个人档案字段规范

**调研目标：** 为设置页档案定义严谨校验与派生规则。

必须覆盖字段：

- `birth_date`（公历）  
- `birth_hour`（0–23 或十二时辰枚举，需二选一推荐）  
- `birth_place`（仅备注 vs 未来真太阳时）  
- 派生：`zodiac_sign`, `shengxiao`（及是否缓存 `day_pillar`）

必须回答：手动覆盖派生字段后，改生日是否重算；推荐交互策略。

### 4.12 确定性与 seed 规范（基础设施）

**调研目标：** 统一全站随机与缓存键规范。

必须给出：

- seed 字符串拼装约定（如 `tarot:{uuid}`）  
- PRNG 推荐（现用 mulberry32 是否足够）  
- 今日缓存键：`user_id + local_date + rule_version`  
- **规则版本号**策略：规则升级后如何避免旧缓存污染

## 6. 建议调研方法

1. **先定流派，再挖细节**，避免中西混用同一套「真理」叙事。  
2. 中文历法优先对照：寿星天文历、中科院紫金山相关民用资料、主流万年历（需点名具体产品/书籍版本）。  
3. 占星优先标明 Tropical / 出生地时区假设。  
4. 塔罗以 RWS 体系为主，注明与透特塔罗等差异，勿混写牌义。  
5. 易学以铜钱法 + 文王卦序为工程主线；高岛易断等变体单列附录。  
6. 对冲突说法使用表格「观点 A / 观点 B / 工程默认」。  
7. 禁止用玄学恐吓语作为规则结论；传统凶杀项需提供「产品软化映射」。
