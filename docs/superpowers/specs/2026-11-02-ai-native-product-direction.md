# V-Life 产品收敛与 Jev 集成方案

日期：2026-11-02。依据：当前工作区实现与 TypeSafe 官方文档。本文是一套推荐方案；除下文列明的备考退场改动，其他内容均未实施。未对 Jev 发起真实推理请求，延迟、中文准确率和节省成本尚未实测。

## 1. 产品定位与核心决定

V-Life 是帮助用户记录、组织和推进生活事项的 AI 原生工作台。用户表达意图，系统将它连接到已有事项，完成有权限的操作并返回可检查的结果。

核心体验：想到就记，记录后自然归位；今天只看要做的事；完成后不必到多个页面重复维护。

确定采用的方向：

- 撤下备考；知识记录保留随想与学习笔记，不重建考试、题库、错题和复习系统。
- 所有可执行任务共享身份。项目组织任务，今日安排任务，日程为任务安排时间。
- 首页升级为「今天」工作台，整合现有今日待办；原今日路径保留兼容跳转。
- 目标并入项目区域的「方向与成果」视图，停止把周/月/年目标作为另一套独立任务清单。
- 随想保留原始表达；学习笔记承载整理后的知识，支持来源关联。
- 生活模块保留领域能力，首页聚合异常和可操作事项。
- Jev 负责窄范围判断，现有生成模型负责表达和复杂拆解，业务代码负责授权、计算、校验和写入。

## 2. 备考退场范围

本轮工作区改动：移除桌面、移动端、搜索、首页、设置的备考入口；旧备考链接转到学习笔记；忽略旧「仅备考」偏好，避免困在已撤下的入口；移除笔记错题反向链接；撤下通用 AI 注册表的旧考公操作和 MCP 的 prep 工具。

保留数据库历史数据、迁移、独立 prep-api 和既有外部连接。学习笔记的旧图片可能依赖备考资产接口，因此兼容渲染暂时保留。旧页面源码暂存但不再挂载。此变更是产品功能退场，不是数据库物理清库；尚未部署，也未撤销用户已有外部连接。

## 3. 页面职责

| 入口 | 职责 | 修改决定 |
| --- | --- | --- |
| 今天 | 执行今天承诺的事项 | 统一输入、今日任务、时间安排、需要处理的提醒；直接完成、改期、打开具体记录 |
| 待办 | 保存和整理所有行动 | 无项目任务可直接记录；项目归属可后补；支持全部和无项目筛选 |
| 项目 | 推进有结束条件的成果 | 保留看板、里程碑、阻塞、进度；关联目标；行动从同一任务库读取 |
| 日程 | 查看时间承诺 | 任务时间块与独立事件并存；支持一个任务多次安排 |
| 随想 | 保存当时的想法 | 默认保存原文；后台建议标签、关联，不擅自改写 |
| 学习笔记 | 沉淀可复用的知识 | 保留课程、Markdown、公式与现有编辑；增加来源与相关内容检索 |
| 生活模块 | 记录真实生活状态 | 保留记账、食材、用品、热量、体重；优先改结束状态和统计口径 |
| 生活日报 | 复盘已发生的事情 | 展示事实及来源，建议可一键转任务；生成日报本身不创建任务 |
| 运势 | 独立的轻松体验 | 保持可隐藏，不参与任务、财务、健康等实际决策排序 |

桌面导航按「今天与行动 / 记录与知识 / 生活」组织。移动端以「今天、待办、项目、更多」为主，统一记录入口始终可达。

## 4. 一件事的生命周期

「把论文实验部分改好，周五前交，明天下午安排一小时。」

1. 保留用户原始输入，识别记录、安排、修改等意图。
2. 检索已有论文项目及任务，判断是新任务还是已有任务的新安排。
3. 任务存截止日期和所属项目；今日安排存计划在哪天做；时间块存起止时间并引用任务。
4. 返回具体结果：任务、所属项目、截止日期、安排时段。可点击修改或撤销。
5. 取消时间块只取消本次安排。经过一小时不自动完成任务。
6. 用户完成一次性任务后，所有视图读同一完成事实；历史安排与实际完成时间分别保存。

重复习惯的母项与每次打卡分开，项目引用同一习惯。单次打卡不结束整个习惯。里程碑表示成果检查点，完成规则独立说明。

数据改造先建立稳定任务标识和旧 ID 映射，按记录核对后迁移。不要用标题相同作为自动合并依据，不做长期双份记录的互相同步。原项目任务的权重、里程碑、状态和历史需保留。

## 5. Jev 核实结果

官方当前稳定版本为 jev-1.14.0，使用 POST /v1/systemone。常规输入是文本/结构化状态。Choice 返回选项及分布，Score 按定义好的等级评价，Noul 返回陈述为真的概率。它不能替代生成模型撰写摘要、标题和长文。

官方列出的价格为每百万输入 token 0.042 美元，输出不计费；默认上下文每请求 64k、每问题 32k。上线固定版本，避免 latest 切换后行为漂移。英文是主要训练语言，中文需单独评估。图片/Box 文档明确仍属实验能力，首版不用于票据或图片识别的生产主链路。

Choice/Score 的 confidence 是分布集中程度的统计量，不等同于该次判断的真实正确率；Noul 没有相同的 confidence 字段。结构符合约束也不意味着语义判断一定正确。

官方旧版 1.13 的限制说明提醒了数字精度、日期比较、无关长上下文等问题。不能把旧版缺陷直接认定为 1.14 的测评结果，但产品设计无需依赖模型做精确计算：这些全部由代码处理。

## 6. Jev 的使用顺序

### 第一批：输入归类与已有记录匹配

- 判断这段输入涉及哪些模块，用多个独立判断支持一条消息包含多种事项，不能用单选强迫只去一个模块。
- 区分查询、记录、修改、计划建议和闲聊；用户明确选择的页面或字段优先，模型不能覆盖。
- 在检索出的真实项目、任务、课程、分类候选中选择关联对象；附加「是否有匹配对象」判断，允许不匹配。
- 判断新内容是否是重复记录、补充信息或全新事项。相似只触发建议，不直接合并或删除。
- 多意图拆分、自由文本字段提取和新标题由生成模型处理；已有原文字段可直接复用。

交互：简单明确的记录沿用用户既有自动执行偏好，并提供操作回执；复杂批量变更呈现一份可检查的结果预览。信息不足时先保留原文，不虚构日期和项目。

### 第二批：知识检索与关联

先由数据库全文检索或已有检索能力找出有限候选，再让 Jev 判断相关性。用户搜索「上次讲条件概率的那段」时，可以得到笔记具体段落和来源。

保存随想后建议关联项目、课程或已有笔记。只有用户提出整理要求时，生成模型才产出整理稿；原文与整理稿分开保存，并有来源关系。暂不建设知识图谱或自动维护第二套笔记库。

### 第三批：今日建议与提醒排序

代码先计算截止时间、空闲时段、是否完成、是否阻塞，排除不可执行候选。Jev 分别评估任务与当前上下文是否匹配、是否影响后续任务等语义因素。代码组合结果，用户置顶和硬期限优先。

今天默认展示用户已安排的任务；AI 建议只占少量位置。显式点击「安排到今天」才改变安排。不要每次刷新都打乱顺序，不把模型评分包装成客观的重要程度。

食材和订阅等硬性到期提醒由规则触发；Jev 可帮助排列软性提醒，但不得压掉必须展示的期限事项。

### 第四批：生成内容检查

生活日报和笔记整理后，用 Jev 判断关键陈述是否有给定记录支持，发现疑点回到来源或交给生成模型重写。数量、金额、完成时间等由代码校验。Jev 检查通过不是事实保证。

## 7. AI 执行架构

复用现有 ai-chat、moduleRegistry、agentDataService、daily_task 工作流和托管模型配置。

统一输入 → 规则检查/权限校验 → Jev 意图判断 → 相关记录检索 → 必要的生成模型提取/规划 → Jev 候选匹配 → 业务校验 → 统一操作执行 → 结果回执。

具体约束：

- Jev 的 key 只在服务端；建立独立适配器，不能将其当成 Chat Completions 模型替换现有 URL。
- AI 侧栏、行内输入和未来其他入口共用同一动作执行服务，逐步收敛当前前端与服务端的执行差异。
- 所有候选 ID 在当前用户权限内检索，执行前再次校验；模型无权授权自己。
- 每次写入有幂等键，结果记录来源与实际写入状态；撤销要检查记录版本，避免覆盖后续编辑。
- 查找、排序和建议可降级；Jev 超时或不可用时用现有模型/明确规则处理，普通手动功能继续可用。
- 多问题只有在相互独立时批量发送；依赖前一步结果的判断分阶段执行。
- 只发送完成判断所需的上下文，不把全部财务和笔记历史传给每次请求。
- 在保存、明确提交、请求建议等事件上触发；不对每个键盘输入发请求。
- 用户纠正优先写成明确、可查看的偏好；不从一次行为推断永久习惯，不声称 Jev 会因此自动微调。

## 8. 非 AI 产品修正

- 目标加入达成标准和关联项目，区分工作完成与结果达成；不直接把任务完成率等同于目标达成率。
- 日程记录关联任务；取消安排不删除任务，安排结束不自动完成任务。
- 学习时长若只有日程依据，改称已安排学习时长；实际投入另有依据才展示。
- 热量无完整记录依据时显示已记录量，不断言达标；所有页面使用统一目标值。
- 食材增加用完、丢弃状态，退出当前库存；保质期状态不再称「充足」。
- 首页提醒直达记录并提供处理动作，按截止与后果排序；始终可查看全部。
- 日报中未记录与未发生区分，建议须明确采纳后才变成任务。

## 9. 落地顺序与验收

1. 备考退场与兼容处理：入口、旧链接、旧偏好、AI 能力清理；随想和笔记功能不回退。
2. 任务身份与执行服务收敛：项目任务可以进入今日，一次性任务仅完成一次；取消时间块不误删任务；重试不重复创建。
3. Jev 在统一输入中影子运行：不改变业务行为，收集匿名化结果、耗时、费用及人工标注。
4. 启用输入归类和匹配：先低影响字段，复杂/不确定项降级；保留手动路径和用户纠正。
5. 首页与今日合并体验、目标收敛、提醒闭环及统计语义修正。
6. 笔记检索、随想关联与日报依据检查。

首批评估至少准备 200 条中文场景，覆盖简短表达、否定、补充、混合意图、同名项目、日期缺失、已存在任务、分类新词和恶意内容。至少留出 30% 不参与提示词调整；报告各类精度、自动覆盖率和错误，不只报总准确率。该规模只用于首轮筛选，不能证明罕见高影响错误已消失。

建议启用标准：低影响自动归类在保留集上精度达到 98%，同时报告样本量与覆盖率；误归属记录单独检查。写入权限、幂等、版本冲突、错误回执由测试强制通过，不用模型分数替代。实际延迟以当前部署区域测 p50/p95，对比未接 Jev 的基线；若没有准确性、速度或成本收益，不强行让该场景经过 Jev。

总成本同时计算 Jev 输入、生成模型、检索和重试。按 2000 输入 token/次估计，10 万次 Jev 请求约 8.40 美元，仅用于量级估算，不是生产账单承诺。
