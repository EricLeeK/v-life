# 待办习惯与例行设计

> **日期：** 2026-09-02
> **状态：** 待审查
> **范围：** 待办清单 + 今日待办 + AI 操作（确认模式）
> **不包含：** 项目看板里已有的项目习惯、工作日/每周频率、跨页跑表、习惯积分

---

## 1. 背景

待办清单现在只有「一次性任务」：勾完可以结束。用户还有两类长期条目：

- **习惯：** 每天都要养成的事（打卡、计数、时长、克制）。要出现在今日待办最上面，且不能靠勾选母卡把它做消失。
- **例行：** 经常要做、但不是在养成自己。母卡常驻；不自动进今日，只在「选今日任务」时置顶。

今日待办如果只显示习惯名称，会显得单薄。不同习惯形态要有不同控件。

这是 AI 驱动的应用：用户经常不自己填表。模型必须替用户选好 `kind` 和习惯形态，确认模式下只让用户点一次「确认执行」。不能在对话里追问「这是习惯还是例行？打卡还是计数？」。

---

## 2. 已锁定的产品决策

| 决策 | 选择 |
|------|------|
| 习惯形态 | 打卡、计数、时长、克制 四种都做 |
| 今日习惯区 | 控件栈，钉在复选框列表之上 |
| 习惯如何进今日 | 未暂停的习惯自动出现，不写 `daily_tasks` |
| 例行如何进今日 | 不自动出现；选择器里置顶；选中后当天就是普通复选框 |
| 待办清单分组 | 习惯单独置顶，默认分类「习惯」；例行留在工作/生活等分类里，只带「例行」标记 |
| 数据落点 | 仍用 `todos` 表，加 `kind`；习惯流水用新表，不复用项目的 `habit_logs` |
| 今日进度环 | 只算下面的复选框任务；习惯自己显示「3 / 4」 |
| 时长第一期 | 只记分钟（+5 / +15 / 自定义），不跑表 |
| 积分 | 第一期习惯不计今日积分 |
| 今日临时添加 | 仍只建一次性待办 |

---

## 3. 概念

三条车道，不要混成一种「常驻」。

| 种类 `kind` | 母卡 | 今日 | 控件 |
|-------------|------|------|------|
| `once` 一次性 | 有复选框，勾完可结束 | 用户选入 `daily_tasks` | 复选框 |
| `routine` 例行 | 无复选框，不因今天勾完而消失 | 不自动出现；选择器置顶；选入后当天复选框 | 当天复选框，勾完只结束今日那条 |
| `habit` 习惯 | 无复选框，默认分类「习惯」 | 自动出现在控件栈 | 按形态：打卡 / ±计数 / 加分钟 / 守住·破功 |

习惯与例行都可以暂停、归档。暂停的习惯不进今日；暂停的例行不出现在选择器。

## 4. 数据

### 4.1 `todos` 新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `kind` | `once` \| `routine` \| `habit` | 默认 `once`。已有行视为一次性。 |
| `habit_type` | `checkin` \| `count` \| `duration` \| `avoidance` \| null | 仅 `kind=habit` 有值。 |
| `habit_target` | number \| null | 计数的目标个数、时长的目标分钟。打卡/克制为 null。 |
| `habit_unit` | text \| null | 如「杯」「个」。时长固定按分钟，可不存或存「分钟」。 |
| `is_paused` | boolean | 默认 false。习惯暂停 → 今日不出现；例行暂停 → 选择器不列出。 |

`is_completed` 对习惯、例行在产品 UI 上不暴露。归档用已有 `is_archived`。

计数/时长创建时 `habit_target` 必须 > 0。打卡/克制禁止填目标。

### 4.2 新表 `todo_habit_logs`

不复用 `habit_logs`（那张表外键挂在 `project_tasks`）。

| 字段 | 说明 |
|------|------|
| `id` | UUID |
| `user_id` | 归属 |
| `todo_id` | 习惯母卡 |
| `log_date` | 本地日 `YYYY-MM-DD`，跨日点沿用设置里的 `day_start_hour` |
| `value` | 数值。打卡为 1；计数为累计杯数/个数；时长为当天已记分钟。 |
| `broken` | 仅克制：true 表示当天破功。成功不写行。 |
| `created_at` / `updated_at` | |

约束：同一用户同一习惯同一 `log_date` 最多一行（upsert）。

克制：当天没有 `broken=true` 的行 → 视为守住，连击 +1。只在破功时写流水。

### 4.3 `daily_tasks`

只承载一次性 + 例行。

- 勾完例行的今日任务：只改 `daily_tasks.is_completed`，**禁止**把母卡 `todos.is_completed` 设为 true。
- 为 `kind=habit` 的母卡创建 `daily_task`：执行层直接跳过，返回「已在今日习惯里」。

### 4.4 连击

仅习惯。按 `log_date` 连续本地日计算。

- 打卡：当天 `value >= 1`
- 计数：当天 `value >= habit_target`
- 时长：当天 `value >= habit_target`
- 克制：当天没有 `broken=true`

撤销当天记录后，连击当场重算。

## 5. 页面与控件

### 5.1 待办清单

新建弹窗增加种类：一次性 / 例行 / 习惯。

- 选习惯：分类默认「习惯」；必选形态；计数/时长必填目标。
- 选例行：分类仍由用户选（工作、生活等），不默认「习惯」。

列表：

- 所有未归档、未暂停的习惯合成一个「习惯」分组，钉在分类视图最上面。行上无复选框，展示形态、目标、今日进度、连击。
- 例行出现在自己的分类里，行上无复选框，带「例行」标记。
- 一次性保持现有复选框。

编辑可改 `kind`。习惯改回一次性或例行：形态字段清空，历史流水保留但不在 UI 展示。

### 5.2 今日待办 · 控件栈

打开页面即渲染所有未暂停习惯，按创建时间（新的在上）。无习惯则不渲染这块，也不放空状态大卡片。

| 形态 | 行上内容 | 操作 |
|------|---------|------|
| 打卡 | 名称、连击、本周 x/7 | 「今日打卡」/「已打卡」，可撤销 |
| 计数 | 名称、进度条、当前/目标 | − / +，到目标即今日完成，允许超过 |
| 时长 | 名称、已记/目标分钟 | +5、+15、自定义分钟；可减回 |
| 克制 | 名称、连击、默认「守住中」 | 「破功」才断；可撤销回守住 |

控件栈标题可显示「今日习惯 · 已达标数 / 总数」。不并入下方圆形进度环。

### 5.3 选今日任务

- 习惯不出现在列表里。
- 未暂停、未归档、且今天还没进 `daily_tasks` 的例行排在最上面。
- 一次性在下面，逻辑与现在相同。

### 5.4 失败

流水写入失败：控件回到写入前，toast 说明。习惯列表加载失败：控件栈顶一条错误，下方复选框列表照常。

## 6. AI 操作

目标：用户用一句话；模型填齐字段；确认模式只展示将要写入的结果，用户点确认。禁止把种类/形态选择题丢回给用户。

### 6.1 模块字段

`todo` create / update 增加：`kind`、`habit_type`、`habit_target`、`habit_unit`、`is_paused`。

`is_completed` 仍只用于一次性。对习惯、例行禁止用 `is_completed=true` 表示「今天做完了」。

新增模块 `habit_log`（表 `todo_habit_logs`）：

| 字段 | 说明 |
|------|------|
| `title` 或 `todo_id` | 定位已有习惯。优先 `todo_id`。 |
| `value` | 计数/时长的**当天累计目标值**或增量，见 6.4 |
| `broken` | 克制破功时为 true |

`daily_task` 不变，但执行层若命中习惯母卡则跳过。

### 6.2 提示词：替用户选好

在 `buildSystemPrompt` 的待办规则与示例里写死：

1. **禁止**在 `summary` 里问「这是习惯还是例行」「打卡还是计数」。没有把握也要选出一个 `kind` 并写入 `operations`，把判断写进 `summary` 供确认，例如：「按每天要养成来处理，建成计数习惯『喝水』8 杯。」
2. **唯一允许空 operations 再问的：** 用户要养成/例行，但连名称都没有（「帮我设个习惯」）。只问名称，不问种类。
3. 推断规则：

| 用户说法 | `kind` | 形态 / 其它 |
|----------|--------|-------------|
| 每天、养成、习惯、打卡、连击 | `habit` | 见下表形态 |
| 经常要做、例行、每次、工作里常做，但没有养成口吻 | `routine` | 分类跟词表（工作/生活等） |
| 今天做、这周做完、一次性 | `once` | 现有逻辑 |
| 在某项目里的习惯 | 仍走 `project_task` `type=habit` | 不要建成个人待办习惯 |
| 重复意图含糊（既像例行又像习惯） | **默认 `routine`** | 避免误自动钉在今日 |

习惯形态：

| 用户说法 | `habit_type` | 默认目标 |
|----------|-------------|----------|
| 做没做、早起、吃药、冥想、写日记 | `checkin` | 无 |
| N 杯 / N 个 / N 次 / 喝水 | `count` | 有数字用数字；喝水没说杯数 → 8；其它没说 → 1 |
| N 分钟、阅读、听力、跑步一段时间 | `duration` | 有数字用数字；没说 → 30 |
| 不…、戒、别熬夜、别点外卖 | `avoidance` | 无 |

4. 习惯 create：`category` 默认「习惯」。例行不要用「习惯」分类。
5. 先 `read_data(module:"todo")` 再 create，标题相同且未归档的习惯/例行 → update 或告知已存在，禁止再插一条。
6. 「今天要做 XXX / 加到今天」：
   - 命中习惯 → 不建 `daily_task`，`summary` 写已在今日习惯里；若用户明显是在报进度（「喝了两杯」「冥想打卡了」）→ 用 `habit_log`。
   - 命中例行 → `daily_task`。
   - 未命中 → 按 3 推断 `kind` 再建；只有一次性/例行才追加 `daily_task`。习惯 create 后会自动出现在今日，不必再 `daily_task`。
7. 「完成 XXX」：
   - 一次性 → `todo` `is_completed=true`（现有）。
   - 例行 → 若已在今日则完成那条 `daily_task`；不在今日则先 `daily_task` 再勾完（加入今天并完成），不要只改母卡。
   - 习惯 → `habit_log`，**禁止** `todos.is_completed`。
8. `summary` 必须用人话写出模型替用户做的选择（种类、形态、目标），方便确认时一眼看到，而不是再问一遍。

### 6.3 确认预览

确认模式下预览行必须带种类，不能只写「新增 待办『喝水』」。

- 习惯：「新增习惯『喝水』· 计数 8 杯」
- 例行：「新增例行『查工作邮箱』· 分类 工作（不自动进今日）」
- 习惯流水：「记录习惯『冥想』今日打卡」
- 把例行加入今天：「加入今日『查工作邮箱』」

用户只点「确认执行」。不要在预览后再生成一轮「请选择类型」的 operations 空包。

直接模式（`ai_mode=direct`）仍一次执行；`summary` 同样要写清种类，事后可撤销（沿用现有 undo 窗口）。

### 6.4 执行层护栏（不依赖模型自觉）

写在 `AIChatPanel` 执行器和/或 Edge 校验里，提示词再狠也会说错。

| 意外 | 处理 |
|------|------|
| 对习惯 `is_completed=true` | 不写母卡。改写为当天达标流水：打卡 `value=1`；计数/时长 `value=habit_target`；克制不把「完成」当成破功（保持守住）。 |
| 对例行 `is_completed=true` | 不写母卡。若今日已有 `daily_task` 则勾完它；没有则先加入今日再勾完。 |
| `daily_task` 指向习惯 | 跳过，结果：「「冥想」已在今日习惯里」 |
| 习惯 create 缺 `habit_type` | 执行器默认 `checkin` |
| 计数/时长缺 `habit_target` 或 ≤0 | 计数默认 1，时长默认 30 |
| 重复标题的未归档习惯/例行 | 不插入，返回已存在 |
| `habit_log` 找不到习惯 | 不自动把一次性改成习惯；返回找不到 |
| 对一次性写 `habit_log` | 拒绝 |
| 克制 `broken` 与 `value` 同时乱填 | 只认 `broken` |
| 计数/时长 `habit_log.value` | 视为**当天累计**（8 表示今天记到 8）。模型应读当天已有值再写；执行器直接 upsert 该日行。 |

### 6.5 示例（写入提示词）

用户：「我想每天喝八杯水」

```json
{"operations":[{"module":"todo","action":"create","data":{"title":"喝水","kind":"habit","habit_type":"count","habit_target":8,"habit_unit":"杯","category":"习惯"}}],"summary":"将新增习惯「喝水」：每天 8 杯（计数）。确认后会自动出现在今日顶部。"}
```

用户：「查工作邮箱要经常做，但先别排进今天」

```json
{"operations":[{"module":"todo","action":"create","data":{"title":"查工作邮箱","kind":"routine","category":"工作"}}],"summary":"将新增例行「查工作邮箱」，放在工作分类。不会自动进今日，选任务时会排在最上面。"}
```

用户：「冥想打卡了」

```json
{"operations":[{"module":"habit_log","action":"create","data":{"title":"冥想","value":1}}],"summary":"将记录习惯「冥想」今日打卡。"}
```

禁止的 summary：「你想建成习惯还是例行？请选择打卡或计数。」（operations 为空）

## 8. 测试

- `kind` 默认 `once`；已有待办不受影响。
- 习惯流水写入、撤销、连击（含跨 `day_start_hour`）。
- 克制：无破功行视为守住；破功后撤销恢复。
- 勾完例行的 `daily_task` 不改母卡 `is_completed`。
- 选择器：习惯不出现；例行在一次性之前。
- 待办清单：习惯分组置顶且无复选框。
- 无习惯时今日不渲染控件栈。
- 执行护栏：习惯 `is_completed` 被拒绝或改写为流水；`daily_task` 指向习惯则跳过。
- 提示词：含「禁止向用户提问种类/形态」、含喝水/例行/打卡三条示例；`createFieldsOf("todo")` 含 `kind`。
- 回归：今日一次性勾选、进度环、临时添加一次性。

不测：跑表、自定义频率、习惯积分、与项目习惯打通。

## 9. 第一期明确不做

- 工作日、每周、每月频率
- 时长跨页跑表
- 习惯计入今日积分 / 进度环
- 今日临时添加里直接建习惯或例行
- 个人习惯与项目看板习惯合并
- 习惯热力月历（控件栈已有连击与本周 x/7）
