这个词为什么叫「边缘」

互联网把机房分成两层：核是少数几个大区域，数据、密钥、模型网关往往集中在这里；边是 CDN 那种铺开的小节点，离你家最近的那一跳。边缘函数，就是把一小段后端放到这些节点上，有请求才醒，跑完就睡。

点切面里的每一层。名称来自网络拓扑，不是营销：你站在地表，边缘贴着你，中心在球心里。

地壳 · 边缘节点

请求先到达离你最近的接入点。边缘函数在这一层醒来：验登录、拼提示词、调模型。密钥留在服务端，浏览器看不见。

键盘 1 地表 · 2 地壳 · 3 地幔 · 4 地核。

三段代码，住在三个地方

「无服务器」不是没有机器，是你不租整台机、不保活进程。有人点一下，平台才在某个节点拉起你的函数。V-Life 的 AI 助手正好跨过这三层。

浏览器

用户的电脑或手机。改这里，npm run dev 立刻能看见。

  • AIChatPanel.tsx 画气泡、点确认
  • 不能放模型密钥
  • 只能 invoke("ai-chat")

边缘函数

全球节点上的一小段 Deno 程序。改这里必须部署，本地前端刷新不够。

  • supabase/functions/ai-chat
  • 提示词、词表、JSON 解析
  • 验 JWT，再去调模型

中心数据

某一个区域里的 Postgres 与密钥。边缘跑完逻辑，仍可能回核读写。

  • todos、分类、登录态
  • Supabase 项目所在区域
  • 模型 API 也是另一座「核」

一次请求的一生

时延不是单单一跳。光纤传播往往只有几十毫秒；冷启动、模型推理才是大头。边缘赢在「传播 + 就近唤醒」，不保证模型本身变快。

  1. 写进仓库

    函数是普通文件。和前端一起版本管理，但运行时不在 Vite 里。

  2. 部署分发

    functions deploy 把同一份代码推到各边缘节点。版本号会跳。

  3. 请求打到近处

    DNS / Anycast 把用户带到最近的 PoP，而不是固定飞去美国。

  4. 冷启动或热启动

    很久没人用，先醒进程（冷）；刚有人用过，就直接跑（热）。

  5. 回核或返回

    只算逻辑，边缘就够。要查库、调模型，再从边缘连到对应的核。

对上你刚部署的那一次

所以改提示词却「刷新没用」：浏览器只托管了调用按钮。真正拼词表、挡 JSON 泄漏的代码，已经印在边缘节点上。你部署的是地壳里的那一层。

前端改完即可预览；parseAgentChat、userVocab、系统提示词必须 supabase functions deploy ai-chat 之后，用户打到的才是新地壳。

图中时延是教学用的光纤估算，不含排队、TLS 与模型推理，不能当基准测试。
