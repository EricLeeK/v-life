# Plan: 统一模块注册表 —— 用单一数据源驱动 Chat 提示词、MCP 工具与客户端执行器

## 目标

把当前散落在 **5+ 处**、且已经"漂移"的模块定义,收敛成**一个 canonical 注册表**,让 `ai-chat` 的系统提示词、`mcp-server` 的工具 schema、以及 `AIChatPanel` 的表/标签/失效键全部从它派生。加一个新模块从"改 5 个地方"降到"改 1~2 个地方",并彻底消除 chat↔MCP 的字段漂移。

**不在本计划范围**(刻意保留,避免过度工程):
- 不引入 native function calling(你 provider-agnostic,`response_format: json_object` + 提示词更可移植)。
- 不引入 Tool RAG / 子代理 / 向量检索(21 个模块不值得)。
- `mapOperationToRow` 的**命令式变换**(JPY 汇率换算、本地时间 ISO 化、错题间隔重复日期)保留在 switch 里——它们本质是代码,不该硬塞进声明式 registry。
- `daily_task` 的 bespoke 流程(找/建 todo + 难度/XP)**不纳入 MCP**(其语义不是 CRUD)。

| 维度 | ai-chat 提示词 | mcp-server TABLES | AIChatPanel |
|---|---|---|---|
| 模块数 | **21** | **18**(缺 project / project_task / daily_task) | 21 |

## 设计:Canonical 注册表

### 文件位置(单一源,零 build step)

**`supabase/functions/_shared/moduleRegistry.ts`** —— 纯数据 + 纯函数,**零外部 import**(无 `Deno.`、无 `https://`、无 `mcp-lite`),因此 Vite、vitest、Deno 三端都能直接 import。

三端接入:
- **`ai-chat`**:相对 import `../_shared/moduleRegistry.ts`(与现有 `hostedAi.ts` 同模式)。
- **`mcp-server`**:同上。
- **前端 `AIChatPanel`**:新增 alias `@modules` → 该文件。需在 3 处注册 alias:`vite.config.ts` + `vitest.config.ts` 的 `resolve.alias`,以及 `tsconfig.app.json` 的 `paths` + `include`(只追加这一个文件,避免把用了 `Deno.env` 的 `hostedAi.ts` 拉进 type-check)。

### 注册表 Schema(Drop-in 覆盖三端需求)

```ts
// _shared/moduleRegistry.ts —— 平台无关,零 import
export type FieldType = "string" | "number" | "boolean" | "date" | "datetime" | "array";

export interface FieldDef {
  name: string;            // 模型面/输入面字段名(如 "course_name")
  type: FieldType;
  required?: boolean;      // create 是否必填
  enum?: string[];         // 枚举值 → 同时进 JSON Schema enum 与提示词 union
  description?: string;    // 中文提示(可选,提示词里可省略以省 token)
  default?: unknown;       // 默认值(executor + 提示词"字段默认值"行)
  aliases?: string[];      // 输入别名(如 food_name 接受 "name")
  internal?: boolean;      // true = 非模型面(DB 列由 executor 计算,如 amount_cny);MCP schema/提示词都排除
}

export interface ResolveSpec {
  from: string;            // 输入字段,如 "project_name"
  toColumn: string;        // 输出列,如 "project_id"
  targetTable: string;     // "projects"
  targetField: string;     // "name"
  required?: boolean;      // 找不到是否 throw
}

export interface ExecutorHints {
  needsUserId?: boolean;          // create 时注入 user.id
  upsert?: string[];              // conflict 列(weight/measurement/civil_checkin = ["user_id","date"])
  nameField?: string;             // 模糊匹配兜底字段(food_name/name/title)
  resolves?: ResolveSpec;         // 外键按名解析
  queryKeys?: string[];           // React Query 失效键
}

export interface ModuleDef {
  key: string;                    // canonical 单数: "todo", "finance" ...
  labelZh: string;                // "待办"
  labelEn: string;                // "To-Do"
  table: string;                  // "todos"
  index: number;                  // 提示词里 ### N. 的序号
  actions: { create?: true; update?: true; delete?: true };
  fields: FieldDef[];             // create 字段(模型面)
  matchFields?: string[];         // update/delete 的 match 字段;缺省=[nameField]
  updateFields?: string[];        // 可更新字段;缺省=全部 fields 名
  notes?: string;                 // 提示词里 **加粗** 的图例/约束/行为规则(自由文本)
  executor?: ExecutorHints;       // 客户端执行器配置
}

export const MODULES: ModuleDef[] = [ /* 21 条,按下述迁移 */ ];

// 纯 helper(平台无关)
export const moduleByKey: Record<string, ModuleDef> = Object.fromEntries(MODULES.map(m => [m.key, m]));
export function tableOf(key: string): string | undefined { return moduleByKey[key]?.table; }

// 提示词生成器(纯函数)—— 替换 ai-chat 里手写的 SYSTEM_PROMPT
export function buildSystemPrompt(): string;
```

**字段语义要点(解决已发现的漂移)**:
- `internal: true` 字段(如 finance 的 `amount_cny`/`exchange_rate`):提示词与 MCP createSchema 都排除;executor/MCP handler 负责计算。
- `enum` 真正进入 MCP JSON Schema(修复"枚举只藏在散文里"),也渲染成提示词 union。
- `course_name`/`project_name` 作为模型面字段保留,`resolves` 描述如何解析成 `course_id`/`project_id`(MCP 与 executor 都用)。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 生成提示词与原文有语义偏差 → 模型行为回归 | 高 | 步骤 2 的 golden diff;snapshot 测试锁住;低 temp(0.1)下 JSON 输出稳健 |
| MCP key 单数化(`todos`→`todo`)破坏现有 MCP 客户端 | 中 | MCP server 目前无鉴权、属实验性;计划里明确标为破坏性变更。若你已有外部消费者,可加一层别名兼容(可选) |
| 前端 import `supabase/` 下文件 → Vite/TS 解析问题 | 低 | 该文件零外部 import;alias + tsconfig include 仅追加此一文件;tree-shaking 去掉未用的 `buildSystemPrompt` |
| MCP finance 行为变更(不再要求客户端传 amount_cny) | 低(正向) | 视为 bug 修复;handler 内部计算 |
